# Elite platform roadmap — honest scope + flagship names

## Reality check (read once)

| Claim | Truth |
|-------|--------|
| **237 games × 5k+ lines each** | That is **millions** of lines and a **multi-year, multi-person** product. Elite studios ship **flagship** titles first, then raise the floor on the catalog. |
| **15k lines per “new” game** | Possible for **one** flagship over many sprints, not for every listing at once. Line count ≠ quality; tests, UX, netcode, and art pipelines matter more. |
| **Same-session “nearby” multiplayer** | Requires **signaling**, optional **WebRTC**, **same-network discovery** (mDNS / QR / room codes). Plan phases; don’t promise full AAA netcode in v1. |

This doc names products, phases, and dependencies so work is **planned**, not chaotic.

---

## Flagship product name (selling point) — **StormGrid Prix**

**StormGrid Prix** — *Proximity Grand Prix*

- **Pitch:** Virtual track league with **10+ distinct world themes**, car classes, and **local / same-network** sessions (room codes first; LAN-style discovery later).
- **Modes (phased):** Time attack → split ghosts → same-Wi‑Fi lobby (room code) → optional WebRTC when infrastructure is ready.
- **Tech direction:** Web-first (Three.js / R3F or Canvas), authoritative room host for casual sync, deterministic physics steps where possible.

## Character + identity (kids-safe, non-editable display name)

- **Random username generator** (curated word lists, no chat, no custom strings at first) — see `web/src/utils/playerAlias.ts`.
- **Locked after assignment** — stored locally; future account system can migrate the same ID.
- **No renames in v1** — reduces moderation surface; document exceptions for schools if needed later.

## Phased delivery (order matters)

### Phase A — Ops & workflow (done / ongoing)

- Production only from **`main`**; develop on branches. See `DEPLOYMENT_WORKFLOW.md`.
- CI build on every PR touching `web/`.

### Phase B — Catalog truth

- One **inventory** per game: purpose, engine, UX tier — generated by `npm run catalog:inventory` (see `GAME_CATALOG_SPRINTS.md`).

### Phase C — Engine depth (repeatable)

- Per **neon engine**: visuals, SFX, tutorial overlay, accessibility — same pattern as Flappy daytime pass.
- Per **slug**: theme hooks (`slugTheme`, tuning), not a separate 5k-line file per title unless that title is a flagship.

### Phase D — Flagships (1–2 at a time)

- **StormGrid Prix** MVP: 1 car mesh style, 3 tracks, single-player + hot-seat or room code.
- Then expand tracks toward **10** and add network layer.

### Phase E — Multiplayer stack

- Room codes (serverless or tiny Node relay) → WebRTC data channels for inputs → lag compensation doc.
